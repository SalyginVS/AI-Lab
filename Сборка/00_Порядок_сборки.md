# Порядок сборки лаборатории

Статус: ACCEPTED RB-11, 2026-10-17. Назначение: провести новую установку по принятому комплекту.
Порядок использования: сверить [паспорт v40](../Паспорт_лаборатории_v40.md), [манифест](manifest/components.tsv), ограничения и входы. Затем последовательно выполнять переходы ниже.
Уровень D принят по завершённым этапам. Уровень R (CLEAN_REBUILD_VERIFIED) не подтверждён. Финальная приёмка D относится к RB-13.

## Входы и внешние зависимости

Скопировать [site.example.env](site.example.env) в приватный файл и заполнить параметры новой площадки. Пустые значения не являются настройками.
Проверить commit комплекта и SHA256SUMS артефактов. Источники версий, digest и хешей находятся в соответствующих runbooks и lock-файлах.
Нужны интернет-источники Ubuntu snapshot и NVIDIA, официальный архив Ollama, Hugging Face и реестр Ollama, npm, Microsoft и Open VSX.
Их доступность может измениться. До установки проверить версии и контрольные суммы, не заменять недоступный источник похожей версией.
Приватный пакет защиты передаётся отдельно. По D-10 его приватный репозиторий создаёт владелец; до этого используется принятый локальный пакет.
Для проверки сетевых ограничений нужен узел вне хостов лаборатории. Правила и карта доступности находятся только в приватном пакете.
Режим работы сервера: по умолчанию выключен, владелец включает его, когда нужны модели или обновления (2026-10-17). Автоматического выключения или перезагрузки на сервере нет (D7). Новая сборка не добавляет такой механизм. Следствие: ночная проверка по cron в 03:00 UTC почти не выполняется (11 ночей из 30 с 18.09 по 17.10). Проверки нужно выполнять после каждого включения.
Действующая лаборатория и vault не являются стендом установки. Новую сборку выполняют на согласованной целевой системе.

| 70, первая точка | [Приватный пакет](70_Безопасность_и_секреты.md) после ОС, до сетевого запуска сервисов | Происхождение и SHA256 пакета, параметры новой площадки, проверки приватной процедуры и внешний сетевой узел; F08 и C05 по приватному приложению |
| 20 | [Ollama](20_Ollama.md) | Receipt архива, preflight, версия и unit по runbook 20; F01, F02, F06, F07. До импорта моделей F04 не является критерием перехода |
| 30 | [Модели](30_Модели.md) | SHA256 каждого источника, корректные model ID и метаданные после импорта; F04 в части inventory; M05 и M06 по embedding после разрешения T-MED |
| 40 | [Q6 wrapper и reasoning repair](40_Q6_runtime.md) | Installed verify, соответствие ID и файлов; F03, F05; разрешённые M01–M04 и M07 подтверждают контекст, профиль, reasoning и изоляцию; сравнение embedding M05–M06 |
| 70, секреты сервера | Создать значения перед запуском 50 | Реестр 70, генератор 50, права и отсутствие значений в журнале; секреты не копировать из публичного репозитория |
| 50 | [Gateway, MCP, RAG, SearXNG](50_Сервисы_Gateway_MCP.md) | Проверки разделов 4–7 runbook 50, F06, M05, M07, M08, M10–M12; оба файла ревизии RB-07.1 должны быть согласованы |
| После 50 | Установить службу проверки по [50](50_Сервисы_Gateway_MCP.md#10-проверка-после-включения) и [90](90_Acceptance_suite.md#служба-после-включения) | Вручную запустить, проверить systemctl status ailab-postboot-check и ~/llm-gateway/logs/postboot/; health 20/20, F04 KNOWN, итог PASS или DRIFT при верном эталоне |
| 70, секреты клиента | Подготовить значения перед 60 | Новые credentials по 70 и приватная проверка доступа; C05 |
| 60 | [Dell и Pi](60_Клиент_Dell.md) | Проверки runbook 60, C01–C04 и M09; Pi только во временном HOME при тестах, Q6 выбирается явно |
| 70, итоговая точка | Повторить контроль после сервисов и клиента | Приватные F08, C05 и внешние сетевые проверки; значения не включать в публичный отчёт |
| 90 | [Итоговая приёмка](90_Acceptance_suite.md) | Полные T-FAST и разрешённый T-MED, оценщик и классификация всех расхождений. T-LONG только отдельной задачей по D-12 |

ID тестов и команды заданы в [90](90_Acceptance_suite.md). T-FAST повторяется после каждого шага для уже установленных компонентов.
Не считать ещё не установленный компонент успешно проверенным. Разрешение на T-MED не является разрешением обновлять действующую систему.
При FAIL остановить переход и сохранить сырой протокол. DRIFT документировать по D-9. REVALIDATE требует согласованной проверки Q6 по ADR-031.
TEST_DEFECT исправлять только при доказанном дефекте теста. Ожидания не менять для получения PASS.

## Известные ограничения

| Ограничение | Следствие и источник |
|---|---|
| Сборка на чистой машине не выполнена | Уровень R не заявляется; [итог программы](../Этапы/2026-10-16_Rebuild_Package/Результаты.md) |
| ОС и пакеты закреплены не полностью | Три исходных несовпадения и непроверенный BIOS; [10](10_Сервер_ОС_и_драйвер.md), [60](60_Клиент_Dell.md) |
| Платформа 147 принята владельцем | Работает 147; Q6 подтверждена T-MED RB-10.1. Два эталона и процедура смены платформы описаны в [90](90_Acceptance_suite.md) и [80](80_Восстановление_и_апгрейд.md) |
| RVN OPTIONAL, model blob не найден | Восстановление из открытых источников заблокировано; [30](30_Модели.md) |
| Принятый сервисный код содержит фиксированные пути | Нужны оператор vladimir и /home/vladimir; совместимость wheel и Chroma ограничена; [50](50_Сервисы_Gateway_MCP.md) |
| Согласованность приватной копии Chroma не доказана | Основной путь: переиндексация lab_docs; sql_knowledge исключена из baseline по H-7; [50](50_Сервисы_Gateway_MCP.md) |
| Pi: override xhigh и объявление image | H-1 сохраняется; vision не подтверждено, OBS-10-01; [60](60_Клиент_Dell.md), [90](90_Acceptance_suite.md) |
| Health-check не проверяет ответ Q6 | Пара RB-07.1 установлена; health 20/20 не заменяет T-MED. Наблюдения обновлены в [90](90_Acceptance_suite.md) |
| Приватный репозиторий пакета ещё создаёт владелец | До него пакет передаётся отдельно; [70](70_Безопасность_и_секреты.md) |
| T-LONG, GPU в контейнере и UI клиента не проверены полностью | Не заменять их коротким ответом модели; [90](90_Acceptance_suite.md), RB-14 |
| Переключение vault ещё не выполнено | Пользовательские файлы и Obsidian относятся к RB-12; [манифест](manifest/README.md) |

Для частичной установки, обновления и отката использовать [80](80_Восстановление_и_апгрейд.md).

Служба этой редакции использует принятый живой эталон 147. Новую сборку по lock RB-06 на 146 проверять с baseline.json; установка живого эталона 147 на неё не означает принятие 147. При несовпадении платформы остановиться и пройти процедуру 80.
