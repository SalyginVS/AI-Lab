**Сервер:** 192.168.0.128 (Ubuntu 22.04, RTX 3090 24 ГБ VRAM, 62 ГБ RAM)
**Шлюз:** ~/llm-gateway/gateway.py v0.7.0 (FastAPI + httpx → Ollama)
**Ollama:** 0.18.0, http://localhost:11434, 13 моделей
**Клиент:** Windows 11, VS Code 1.112, GitHub Copilot Free plan, Continue.dev v1.2.17

## Что сделано

### Правка gateway.py: защищённый парсинг ошибок от Ollama

В блоке `chat_completions` улучшена обработка `httpx.HTTPStatusError` (строки 923–930). Добавлен try/except вокруг `e.response.json()` — при невалидном JSON в теле ошибки от Ollama (HTML, пустой ответ) вместо вторичного исключения теперь подставляется строковое описание ошибки. Результат передаётся в `classify_ollama_error()` для формирования OpenAI-совместимого error-ответа. Без этой защиты клиент (VS Code / Copilot) мог получить «Internal gateway error» без деталей вместо структурированной ошибки.

### Предварительные условия

VS Code 1.112 (вышел 2026-03-18) с GitHub Copilot Free plan. BYOK (Bring Your Own Key — «подключи свой ключ/модель») доступен для планов Free / Pro / Pro+. НЕ доступен для Business / Enterprise.

### Путь B — customOAIModels

**Статус: НЕ ПРОВЕРЕН**

Настройка `github.copilot.chat.customOAIModels` — встроенная в Copilot функция для произвольных OpenAI-совместимых endpoint'ов. По документации Microsoft, на момент v1.104 доступна только в VS Code Insiders. Статус в стабильном VS Code 1.112 не проверен.

### Agent mode / Tools

**Статус: НЕСТАБИЛЕН**

При использовании `qwen3-coder:30b` в Copilot Agent mode:
- Tools UI доступен (после `#` показывается список инструментов)
- Явные запросы вида `Use #codebase` приводят к «болтливым» текстовым ответам без исполнения инструмента
- При первой попытке tool calling запрос зациклился: потребление GPU выросло, потребовался `ollama stop` и перезапуск сервиса
- gateway.py корректно логировал `tool_calls detected: 1 call(s)` — проброс tool_calls через шлюз работает, проблема на стороне модели

**Корневая причина:** Copilot Agent mode использует собственный набор инструментов (workspace search, file read, terminal и др.) со своим промпт-форматом. Локальные модели 30B-класса недостаточно дисциплинированы для этого протокола — в отличие от GPT-4o/Claude Sonnet, которые специально дообучены под Copilot tools. Модель генерирует текст о том, что «хочет» использовать инструмент, вместо того чтобы вернуть корректный tool_call JSON.

## Обнаруженные проблемы

### 1. Зацикливание tool calls в Copilot Agent mode (КРИТИЧНО для Agent)

**Симптом:** Запрос с tools приводит к зацикливанию, потребление GPU растёт, требуется `ollama stop`.

**Причина:** Copilot Agent промпт-формат ожидает высокодисциплинированное поведение модели при tool calling. Локальные модели 30B-класса не дообучены под формат инструментов Copilot — они генерируют текст вместо tool_call JSON или входят в бесконечный цикл «думаю → вызываю → думаю → вызываю».

**Статус:** Неисправимо на стороне шлюза. Требует либо более качественных моделей, либо адаптации Copilot Agent промптов под локальные модели (что невозможно — промпты контролируются Microsoft).

### 2. «Болтливые» ответы вместо исполнения инструментов (СРЕДНЕ)

**Симптом:** При запросе `Use #codebase` модель отвечает текстом о том, что она ищет в codebase, но не выполняет реального поиска.

**Причина:** Та же, что и п.1 — модель не следует tool calling протоколу Copilot.

### 3. Дублирование моделей в picker (НИЗКО)

**Симптом:** Одна и та же модель (qwen3-coder:30b) видна дважды: под Ollama и под OAI Compatible.

**Решение:** Не критично. Можно скрыть лишние через Language Models → visibility controls.

## Итоговая рекомендация

**Continue.dev остаётся основным инструментом.** Copilot BYOK полезен как дополнительный интерфейс для plain chat, но не заменяет Continue.dev ни в одном критическом сценарии:

- **Agent mode** — работает только в Continue.dev (qwen3-coder, glm-flash)
- **Autocomplete** — работает только в Continue.dev (FIM через Ollama)
- **Context providers** — работают только в Continue.dev
- **Приватность** — Continue.dev полностью локален, Copilot отправляет данные в GitHub

**Рекомендация по путям:**
- **Путь C (OAI Compatible extension)** — оставить как запасной чат-интерфейс, работает через шлюз (логирование, reasoning policy, валидация)
- **Путь A (Ollama напрямую)** — альтернатива, если extension не нужен (минует шлюз, нет логирования)
- **Путь B (customOAIModels)** — проверить при случае, потенциально наиболее «чистый» вариант (встроен в Copilot без расширений)
