## 2. Ключевое открытие: Autocomplete = FIM, не chat

**Autocomplete в Continue.dev работает через FIM (Fill-in-the-Middle)** — специальный промпт-формат с токенами `<|fim_prefix|>`, `<|fim_suffix|>`, `<|fim_middle|>`. Модели для autocomplete должны быть обучены на этом формате.

Важные следствия:
1. **Chat-модели (qwen3, deepseek-r1 и т.д.) НЕ подходят для autocomplete** — они не обучены FIM
2. **Autocomplete идёт напрямую в Ollama** (provider: ollama), минуя шлюз gateway.py
3. **Шлюз не нужен для autocomplete** — Ollama `/api/generate` поддерживает FIM нативно
4. В config.yaml используется `roles: [autocomplete]` и `autocompleteOptions`

## 3. Обнаруженные проблемы с qwen3.5 в Ollama (март 2026)

### Tool calling qwen3.5 — СЛОМАН в Ollama

Подтверждено (GitHub issue #14493, #14745):
- Ollama роутит qwen3.5 tool calls через **неправильный pipeline** (Hermes-style JSON вместо Qwen3-Coder XML)
- renderer-сторона сломана: multi-turn промпты содержат незакрытые `<think>` теги
- Тесты tool-call thinking в коде Ollama закомментированы
- v0.17.3 частично исправил парсинг, v0.17.6 исправил ещё часть, но проблемы остаются
- qwen3.5:9b (issue #14745, 9 марта 2026) — иногда печатает tool call как текст вместо выполнения
- qwen3.5:35b (issue #14662) — второй запрос зависает на 30-60 сек на RTX 3090

### Вывод

- **qwen3.5:35b** — использовать ТОЛЬКО как experimental reasoning, **без tools**
- **qwen3.5:9b** — можно для chat/vision, tools — с оговорками
- **Для Agent mode — оставить qwen3-coder:30b** как единственную надёжную модель

## 8. Справочная информация

### Архитектура подключения

```
VS Code (Windows 11)
  └── Continue.dev v1.2.17
        ├── Chat/Edit/Agent → gateway.py :8000 /v1/chat/completions
        │                      └── Ollama :11434 /api/chat
        ├── Model list     → gateway.py :8000 /v1/models
        ├── Autocomplete   → Ollama :11434 напрямую (FIM, /api/generate)
        └── Embeddings     → Ollama :11434 напрямую
```

### Почему autocomplete минует шлюз

- Continue для autocomplete использует FIM-формат через Ollama `/api/generate` (не `/api/chat`)
- Шлюз gateway.py реализует только `/v1/chat/completions` — он для FIM бесполезен
- При `provider: ollama` Continue общается с Ollama напрямую
- При `provider: openai` Continue общается через OpenAI-совместимый API (наш шлюз)

### Модели для autocomplete — почему FIM, а не chat

Autocomplete-модель обучена на специальном FIM-формате: получает prefix (код до курсора) и suffix (код после курсора), предсказывает что между ними. Chat-модели (GPT, Claude, Qwen3, DeepSeek-R1) НЕ обучены на этом формате — они не дают полезных дополнений кода.

Рекомендованные FIM-модели: qwen2.5-coder:1.5b (минимальная), qwen2.5-coder:7b (оптимальная), qwen2.5-coder:14b (максимальная, избыточна для autocomplete).

### Ключевые ограничения

- **OLLAMA_NUM_PARALLEL=1** — один запрос за раз. Autocomplete и chat конкурируют
- **Холодный старт** при переключении моделей ~8-30 сек (поэтому MAX_LOADED_MODELS=2)
- **qwen3.5 tool calling сломан** в Ollama (март 2026) — не использовать для Agent mode
- **FIM для qwen3-coder:30b** — Ollama не добавил FIM-шаблон (open issue #12387)
- **GLM-4.7-Flash** — требует Ollama ≥0.14.3, возможны проблемы с chat template
