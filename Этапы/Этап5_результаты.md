## Что сделано

### P1 — system_fingerprint (блокер OpenAI SDK)

OpenAI Python SDK парсит ответы через Pydantic-модель ChatCompletion, которая ожидает поле `system_fingerprint`. Все зрелые прокси (LiteLLM, LM Studio, vLLM) возвращают его как null. Добавлено `"system_fingerprint": null` в `build_openai_response()` (non-stream) и `format_sse_chunk()` (stream).

### P2 — ChatMessage: multimodal, name, tool_calls

`ChatMessage.content` расширен с `str` до `Union[str, list, None]`. Добавлены поля `name`, `tool_calls`, `tool_call_id`. Новая функция `convert_message_for_ollama()` конвертирует OpenAI-формат сообщений в Ollama-формат: извлекает base64 из data URI image_url блоков в `images[]`, HTTP URL пробрасывает как есть, tool_calls/tool_call_id передаёт для function calling.

### P3 — stop, tools, tool_choice, tolerant parsing

Параметр `stop: Union[str, list, None]` добавлен с маппингом `str → [str]` → `options.stop`. Параметры `tools` и `tool_choice` пробрасываются top-level в payload Ollama (не внутри options) для моделей с function calling (Qwen, Llama). `ConfigDict(extra="ignore")` на обеих Pydantic-моделях — неизвестные параметры от клиента (logprobs, logit_bias, n, user, response_format, service_tier и пр.) молча игнорируются.

### P4 — Stream usage: reasoning_tokens

В `stream_generator()` добавлены аккумуляторы `total_thinking_len` и `total_content_len`. В финальном чанке (done: true) eval_count разделяется пропорционально на `completion_tokens` (ответ) и `reasoning_tokens` (thinking), как в non-stream режиме. Ранее stream отдавал сырой eval_count без разделения.

### P5 — service_tier

Поле `"service_tier": null` добавлено в non-stream и stream ответы для forward compatibility с newer OpenAI SDK versions.

### P6 — /v1/models: парсинг modified_at

`parse_ollama_timestamp()` парсит ISO datetime из Ollama (включая наносекунды, которые Python не принимает — обрезаются до микросекунд). Поле `created` в `/v1/models` теперь содержит реальную дату модификации модели, а не `time.time()`.

### P7 — Аутентификация Bearer token

Middleware `auth_middleware()` проверяет заголовок `Authorization: Bearer <key>` против переменной окружения `LLM_GATEWAY_API_KEY`. `/health` exempt. Если переменная не задана — доступ открыт. Формат ошибки 401 — OpenAI-совместимый. `/health` отображает `auth_enabled: true/false`.
