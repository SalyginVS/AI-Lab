## 2. Установка и диски

Загрузите носитель в UEFI и создайте обычную установку Ubuntu Server без LVM.
Имя оператора задаётся параметром `LAB_OPERATOR`.

| Диск | Раздел | Файловая система | Точка |
|---|---|---|---|
| NVMe | EFI, 1 GiB | vfat | /boot/efi |
| NVMe | остальное пространство | ext4 | / |
| SATA SSD | один раздел | ext4 | /srv/ai-test |
| NVMe, файл | /swap.img, файл 8 GiB | swap | none |

Перед разметкой подтвердите диски командой `lsblk -o NAME,SIZE,MODEL,FSTYPE,MOUNTPOINTS`.
Установщик уничтожает данные выбранных разделов. Этот маршрут относится к пустой площадке.
Получите новые UUID через `lsblk -f` и `blkid`.
Запишите их в `LAB_ROOT_UUID`, `LAB_EFI_UUID`, `LAB_DATA_UUID`.

```fstab
UUID=@LAB_ROOT_UUID@ / ext4 defaults 0 1
UUID=@LAB_EFI_UUID@ /boot/efi vfat defaults 0 1
/swap.img none swap sw 0 0
UUID=@LAB_DATA_UUID@ /srv/ai-test ext4 defaults,noatime,nofail,x-systemd.device-timeout=10s 0 2
```

Заполните маркеры и внесите строки в /etc/fstab.
Существующие строки изменяйте по месту. Не создавайте дубли.
Если swap-файл отсутствует, создайте его:

```bash
sudo fallocate -l 8G /swap.img
sudo chmod 600 /swap.img
sudo mkswap /swap.img
sudo swapon /swap.img
sudo mkdir -p /srv/ai-test
sudo findmnt --verify --verbose
sudo mount -a
findmnt -T /
findmnt -T /boot/efi
findmnt -T /srv/ai-test
swapon --show --bytes
```

Ожидаются ext4, vfat, ext4 и /swap.img.
На исходном сервере swapon показывал 8589930496 доступных байт для файла 8 GiB.
При ошибке UUID остановитесь до перезагрузки.

## 3. Снимок APT и точные версии

Задайте `LAB_BUILD_ROOT` как путь к рабочей копии, `LAB_PLATFORM_PACKAGE` как путь к `artifacts/platform`.
[Документация Ubuntu Snapshot Service](https://snapshot.ubuntu.com/) подтверждает поддержку Ubuntu 24.04,
поля deb822 `Snapshot:` и команды `apt update --snapshot T` перед `apt install --snapshot T`.
Здесь используется `Snapshot: 20261010T120000Z` в обоих блоках источников.
Так выбор T действует и для команд без отдельного флага.

```bash
cd "$LAB_PLATFORM_PACKAGE"
sha256sum --check SHA256SUMS
sudo install -m 0644 ubuntu.snapshot.sources /etc/apt/sources.list.d/ubuntu.sources
sudo apt update
apt policy linux-generic nvidia-driver-595-open docker.io containerd
mapfile -t platform_packages < <(cat key-packages.lock base-packages.lock | sort -u)
sudo apt install "${platform_packages[@]}"
dpkg-query -W -f='${Package}=${Version}\n' \
  linux-generic linux-image-6.8.0-146-generic \
  linux-modules-nvidia-595-open-6.8.0-146-generic nvidia-driver-595-open docker.io containerd
```

Оба lock-файла содержат только проверенные `имя=версия`.
`base-packages.lock` содержит ручные базовые пакеты вне сетевого этапа и CTK.
Автоматические зависимости выбираются из того же снимка.
Не заменяйте установку lock командой full-upgrade.
Если зависимости не разрешаются, сохраните вывод и остановитесь. Другие версии автоматически не выбирайте.

Ожидаются ядро 6.8.0-146.146, NVIDIA 595.99.02-0ubuntu0.24.04.1,
Docker 29.1.3-0ubuntu3~24.04.2 и containerd 2.2.1-0ubuntu1~24.04.3.
Python 3: 3.12.3-0ubuntu2.1; python3-pip: 24.0+dfsg-1ubuntu1.3.
Разрешимость полного lock на новой ОС проверяется в RB-14. RB-06 подтверждает наличие точных версий.

## 4. Драйвер и ядро

История содержит исходную установку:
`apt-get install -o DPkg::options::=--force-confnew -y nvidia-driver-590-open linux-modules-nvidia-590-open-generic`.
Текущая 595-я ветка получена последующими обновлениями.
Отдельная команда её первичной установки в доступном history.log не найдена.
Зафиксирован `apt full-upgrade -y` от 2026-10-02.
P-1 прямо подтверждает обновление 595.91.07 до 595.99.02 через `/usr/bin/unattended-upgrade` 2026-10-16 в 09:52:15.
Причина именно этого обновления H-5 теперь подтверждена журналом APT.

Lock включает предсобранные модули для 6.8.0-146 и установленный на сервере nvidia-dkms-595-open.
Наличие DKMS-пакета не доказывает, что загружен именно его модуль.
`dpkg -S` относит параметры модуля к nvidia-kernel-common-595.

```bash
sudo install -m 0644 "$LAB_PLATFORM_PACKAGE/nvidia-graphics-drivers-kms.conf" \
  /etc/modprobe.d/nvidia-graphics-drivers-kms.conf
sudo update-initramfs -u -k 6.8.0-146-generic
sudo update-grub
mokutil --sb-state
sudo reboot
```

После загрузки:

```bash
uname -r
nvidia-smi --query-gpu=name,driver_version,memory.total --format=csv
modinfo -F version nvidia
modinfo -n nvidia
cat /sys/module/nvidia_drm/parameters/modeset
grep -E 'PreserveVideoMemoryAllocations|TemporaryFilePath' /proc/driver/nvidia/params
```

Ожидаются `6.8.0-146-generic`, RTX 3090, драйвер `595.99.02`,
modeset=Y, PreserveVideoMemoryAllocations=1 и TemporaryFilePath=/var.
При другой версии выберите нужное ядро в меню загрузки и повторите проверку.
Захваченный /etc/default/grub не копируется целиком: параметры площадки требуют отдельного заполнения.

P-1 показал SecureBoot disabled на исходном сервере.
Если на новой площадке Secure Boot включён, используйте подписанные Ubuntu-модули для нужного ядра.
Проверьте `modinfo -F signer nvidia` и фактическую загрузку.
При использовании DKMS может потребоваться регистрация Machine Owner Key через штатный диалог Ubuntu.
Не считайте установку deb-пакета доказательством загрузки драйвера.
Отключение Secure Boot не является автоматическим шагом.
Системный CUDA toolkit не нужен: Ollama содержит собственные CUDA-библиотеки.

## 5. Docker и NVIDIA Container Toolkit

Docker исходно установлен командой `apt -y install docker.io` 2026-02-20.
Compose: `apt install docker-compose-v2` 2026-09-05.
Docker и containerd берутся из Ubuntu. Репозиторий Docker не добавляется.
Они уже установлены и закреплены на шаге 3.

CTK (Container Toolkit) исходно установлен через `apt install -y nvidia-container-toolkit` 2026-03-14.
Тогда была версия 1.19.0-1. Сейчас все четыре NVIDIA-пакета имеют версию 1.20.1-1.
[Индекс NVIDIA](https://nvidia.github.io/libnvidia-container/stable/deb/amd64/Packages)
содержит эти версии и SHA256. Контрольные суммы записаны в `CTK-SHA256SUMS`.
Системные зависимости libc6, libcap2 и libseccomp2 подтверждены в подписанном снимке.
Отдельная подпись индекса NVIDIA в RB-06 не проверена.

```bash
mkdir -p "$LAB_EVIDENCE_DIR"
curl --fail --location https://nvidia.github.io/libnvidia-container/gpgkey \
  --output "$LAB_EVIDENCE_DIR/nvidia-container-toolkit.asc"
gpg --dearmor --output "$LAB_EVIDENCE_DIR/nvidia-container-toolkit-keyring.gpg" \
  "$LAB_EVIDENCE_DIR/nvidia-container-toolkit.asc"
sudo install -m 0644 "$LAB_EVIDENCE_DIR/nvidia-container-toolkit-keyring.gpg" \
  /usr/share/keyrings/nvidia-container-toolkit-keyring.gpg
sudo install -m 0644 "$LAB_PLATFORM_PACKAGE/nvidia-container-toolkit.list" \
  /etc/apt/sources.list.d/nvidia-container-toolkit.list
sudo apt update
mapfile -t ctk_packages < "$LAB_PLATFORM_PACKAGE/ctk-packages.lock"
sudo apt install "${ctk_packages[@]}"
dpkg-query -W -f='${Package}=${Version}\n' \
  nvidia-container-toolkit nvidia-container-toolkit-base libnvidia-container1 libnvidia-container-tools
```

Для проверки скачанных deb до установки выполните `apt download` четырёх строк lock в пустом каталоге.
Затем выполните `sha256sum --check "$LAB_PLATFORM_PACKAGE/CTK-SHA256SUMS"`.
При несовпадении остановитесь. В RB-06 deb-пакеты не скачивались.

`dpkg -S /etc/docker/daemon.json` не нашёл владельца.
APT history не содержит запусков nvidia-ctk. Способ создания исходного файла не установлен.
Поэтому восстанавливается захваченный daemon.json. Ему не приписывается непроверенная команда генерации.

```bash
sudo install -d -m 0755 /etc/docker
sudo install -m 0644 "$LAB_PLATFORM_PACKAGE/daemon.json" /etc/docker/daemon.json
sudo systemctl enable --now containerd docker
sudo systemctl restart docker
sudo usermod -aG docker "$LAB_OPERATOR"
docker --version
docker compose version
sudo docker info --format '{{json .Runtimes}}'
```

Ожидаются Docker 29.1.3, Compose v2 и зарегистрированный runtime `nvidia`.
На исходной системе nvidia не объявлен default runtime.
Членство оператора в docker применяется после нового входа.
Группы video и render для Ollama настраиваются в `20_Ollama.md`.

Задайте `LAB_GPU_TEST_IMAGE` как одобренный образ с digest, содержащий nvidia-smi или совместимый с его внедрением NVIDIA runtime.
Выбор и получение тестового контейнера относятся к RB-10. Он не включён в дистрибутив RB-06.

```bash
sudo docker run --rm --gpus all "$LAB_GPU_TEST_IMAGE" nvidia-smi
```

Ожидаются RTX 3090 и драйвер 595.99.02 внутри контейнера.
При отсутствии GPU остановитесь до установки сервисов лаборатории.

## 6. Политика обновлений

Решение владельца D-9 от 2026-10-16: выбран вариант (а), автоматические обновления как сейчас, без hold.
Первоначальная сборка выполняется с фиксированным Snapshot.
После её проверки применяется вариант (а).
Смена ядра или драйвера требует ревалидации Q6 по ADR-031. Проверка дрейфа версий выполняется в RB-10.
Список платформенных пакетов для обоих вариантов:

```bash
mapfile -t platform_holds < <(
  dpkg-query -W -f='${Package}\t${db:Status-Abbrev}\n' |
  awk '$2=="ii" {print $1}' |
  grep -E '^linux-(generic|image|modules|headers)|595|^docker.io$|^docker-compose-v2$|^containerd$|^runc$|^nvidia-container|^libnvidia-container'
)
```

### Вариант (а): как сейчас

Обычный архив и автоматические обновления.
RB-07 A.0: захваченный `50unattended-upgrades` совпадает байт в байт с файлом по умолчанию
`/usr/share/unattended-upgrades/50unattended-upgrades` из пакета `unattended-upgrades=2.9.1+nmu4ubuntu1`
снимка `20261010T120000Z`. SHA256: `ac8eb4fbfeb483815e5a7a224a86d4242f70bdb41ceb84333b05a9a39f5296be`.
Отдельный артефакт этого файла не требуется.

```bash
sudo sed -i '/^Snapshot:/d' /etc/apt/sources.list.d/ubuntu.sources
sudo apt-mark unhold "${platform_holds[@]}"
sudo install -m 0644 "$LAB_PLATFORM_PACKAGE/20auto-upgrades" /etc/apt/apt.conf.d/20auto-upgrades
sudo systemctl enable --now unattended-upgrades
sudo apt update
apt-mark showhold
apt-config dump | grep -E 'APT::Periodic|Unattended-Upgrade::Allowed-Origins'
```

Ожидаются отсутствие platform hold и включённые ежедневные обновления.
Изменения ядра, драйвера и runtime требуют ревалидации Q6 по ADR-031.

### Вариант (б): закрепить платформу

Альтернативный вариант, не выбран владельцем по D-9.
Автоматически обновляются остальные разрешённые пакеты безопасности:

```bash
sudo sed -i '/^Snapshot:/d' /etc/apt/sources.list.d/ubuntu.sources
sudo apt-mark hold "${platform_holds[@]}"
sudo install -m 0644 "$LAB_PLATFORM_PACKAGE/20auto-upgrades" /etc/apt/apt.conf.d/20auto-upgrades
sudo systemctl enable --now unattended-upgrades
sudo apt update
apt-mark showhold
sudo unattended-upgrade --dry-run --debug
```

Проверьте удержание метапакетов ядра, image/modules/headers, 595-й ветки, Docker, Compose, runc, containerd и CTK.
Обновление удерживаемых пакетов требует отдельного окна, unhold, проверки и повторного hold.
Фиксированный Snapshot снимается в обоих вариантах, иначе остальные обновления также останутся замороженными.
