## Что сделано

### 7C-0 — Embeddings для индексации

Добавлена embed-модель `transformers.js` (all-MiniLM-L6-v2) в config.yaml. Это встроенная модель Continue, работающая внутри VS Code extension host. Нулевая нагрузка на Ollama, не конкурирует с chat/agent/autocomplete за OLLAMA_NUM_PARALLEL=1.

Индексация проекта запускается автоматически при открытии workspace. Разблокирует context providers `@Code` (поиск функций/классов по проекту) и `@Repository Map` (карта репозитория с сигнатурами).

Выбор обоснован: при OLLAMA_NUM_PARALLEL=1 серверная embed-модель (nomic-embed-text или qwen3-embedding) блокировала бы chat/agent при индексации (десятки-сотни запросов подряд). transformers.js работает параллельно в процессе VS Code.

Настроены три уровня правил, загружаемых в system message:

| Уровень | Файл | Где хранится | Содержание |
|---|---|---|---|
| Встроенный | Default agent system message | Continue | Базовые инструкции агента |

## Обнаруженные проблемы и решения

### 1. extraBodyProperties на неправильном уровне (КРИТИЧНО)

**Симптом:** `400 Ollama rejected request: Value looks like object, but can't find closing '}' symbol` при запросах через glm-flash.

**Причина:** `extraBodyProperties` был расположен на уровне модели (рядом с `requestOptions`), а должен быть вложен внутрь `requestOptions`. При неправильном расположении Continue передавал его как отдельное поле в JSON payload, ломая структуру запроса.

**Решение:** Перенести `extraBodyProperties` внутрь `requestOptions` у всех моделей.

### 2. Embed-модель transformers.js требует поле model (КРИТИЧНО)

**Симптом:** `Failed to parse config: models.0: Invalid input` при определении embedder без поля `model`.

**Причина:** YAML-парсер Continue 1.2.17 требует обязательное поле `model` у всех записей в `models`, даже для встроенных провайдеров.

**Решение:** Указать `model: all-MiniLM-L6-v2` явно.

### 3. Секция context: сбрасывает дефолтные провайдеры (СРЕДНЕ)

**Симптом:** После добавления секции `context:` пропали Files, Current File и другие дефолтные провайдеры.

**Причина:** При наличии секции `context:` Continue показывает ТОЛЬКО явно перечисленные провайдеры, дефолтный набор сбрасывается.

**Решение:** Перечислить все нужные провайдеры явно, включая те, которые были в дефолте.

### 4. Prompts: файлы .md работают из prompts/, а не из rules/ (СРЕДНЕ)

**Симптом:** Файлы `.md` с `invokable: true` в `%USERPROFILE%\.continue\rules\` не появлялись в списке `/`.

**Причина:** Continue 1.2.17 ищет prompt-файлы в `.continue/prompts/`, а не в `.continue/rules/`. Rules и prompts — разные папки.

**Решение:** Определить prompts через секцию `prompts:` в config.yaml (работает надёжно). Альтернатива: файлы `.md` в `.continue/prompts/`.

### 5. Проектные rules требуют Reload Window (НИЗКО)

**Симптом:** После создания `.continue/rules/01-project.md` в workspace правило не появлялось в UI.

**Причина:** Continue не отслеживает появление новых файлов в `.continue/rules/` в реальном времени.

**Решение:** `Ctrl+Shift+P` → `Developer: Reload Window`.

## Грабли Continue 1.2.17 (дополнение к Этапам 7A-7B)

- **extraBodyProperties** — должен быть ВНУТРИ `requestOptions`, не на уровне модели. Иначе 400 от Ollama.
- **transformers.js embedder** — требует явное поле `model: all-MiniLM-L6-v2`, без него парсер падает.
- **Секция context:** сбрасывает дефолтные провайдеры — все нужные перечислять явно.
- **Prompts** работают через `prompts:` в config.yaml. Файлы `.md` с `invokable: true` — из `.continue/prompts/`, НЕ из `.continue/rules/`.
- **Проектные rules** — требуют `Developer: Reload Window` при первом создании.
- **capabilities: [tool_use]** — НЕ требуется для qwen3-coder и glm-flash, Continue автодетектит.
