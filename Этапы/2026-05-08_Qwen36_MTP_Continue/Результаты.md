# Этап — Qwen3.6 27B MTP / Continue bounded lane

## Задача
Подключить Qwen3.6 27B MTP lane к существующему OpenAI-compatible gateway и проверить использование из Continue / VS Code как bounded executor profile.

## Результат
Интеграция выполнена: Continue profile `qwen36-27b-mtp-bounded` успешно вызывает модель `qwen3.6-27b-lorbus-mtp-triton-ctx4k` через gateway provider `vllm-mtp`.

Финальный статус:

```text
STATUS=PASS_WITH_MINOR_CONTRACT_DEVIATION
ROLE=controlled bounded executor candidate
PRODUCTION_AUTONOMOUS_AGENT_READY=no
```

## Что сделано

### Подэтап 1 — MTP backend и gateway route

- vLLM MTP backend доступен на `127.0.0.1:8027`.
- Gateway `0.12.0` остаётся общим OpenAI-compatible integration layer.
- Gateway route через provider `vllm-mtp` подтверждён логами и `/health`.

### Подэтап 2 — Continue profile

Добавлен отдельный bounded profile:

```yaml
name: qwen36-27b-mtp-bounded
provider: openai
model: qwen3.6-27b-lorbus-mtp-triton-ctx4k
apiBase: http://192.168.0.128:8000/v1
roles: [chat, edit, apply]
defaultCompletionOptions:
  temperature: 0.1
  maxTokens: 512
requestOptions:
  timeout: 600000
  extraBodyProperties:
    num_ctx: 4096
    max_tokens: 512
    reasoning_effort: "none"
```

### Подэтап 3 — Исправления по интеграции

- Исправлена ошибка gateway streaming handling: response body vLLM нельзя читать как обычный body после streaming without explicit read/close.
- Исправлено несоответствие `max_tokens`: Continue пытался запрашивать 4096 output tokens при context window 4096.
- Установлен безопасный профиль `maxTokens=512` / `max_tokens=512`.

### Подэтап 4 — Коррекция source-of-truth

После ошибочного ухода в server-side repo hygiene принято решение: сервер `192.168.0.128` не является Git/source-of-truth контуром. Удалены server-side Git metadata:

```text
/home/vladimir/llm-gateway/.git
/home/vladimir/git-remotes/llm-gateway.git
/home/vladimir/git-remotes
```

Проверка после удаления: `llm-gateway.service=active`, `/health=200`, gateway version `0.12.0`, `pipelines_count=6`.
