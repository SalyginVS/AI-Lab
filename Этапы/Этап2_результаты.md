**Шлюз:** ~/llm-gateway/gateway.py v0.2.0 (FastAPI + httpx → Ollama)

## Что сделано

### Reasoning Policy

Реализована четырёхуровневая политика reasoning через параметры `reasoning.effort` (объект, формат OpenAI) и `reasoning_effort` (строка, формат прокси-серверов). Маппинг на Ollama `think: true/false`. Thinking никогда не утекает в `content` — отдаётся через отдельное поле `reasoning_content` только при effort >= medium. Usage разделяет `completion_tokens` (только ответ) и `reasoning_tokens` (оценка по пропорции текста).

### Depth-over-Speed

Стратегия: приоритет глубины контекста над скоростью генерации. RAM 62 ГБ используется как расширение VRAM через CPU offload. Дефолтный `num_ctx` поднят с 4096 до 8192. Клиент может запросить до 32768 через API. Проброс `num_gpu` и `num_batch` позволяет управлять CPU offload per-request.

### Ollama — оптимизация памяти

Настроено через systemd override (OLLAMA_FLASH_ATTENTION=1, OLLAMA_KV_CACHE_TYPE=q8_0). Flash Attention снижает расход VRAM. KV cache q8_0 ужимает кэш внимания вдвое. OLLAMA_NUM_PARALLEL=1, OLLAMA_MAX_LOADED_MODELS=1 — защита от деградации.

### Новые эндпоинты

`GET /v1/models` — список моделей в формате OpenAI (обёртка над /api/tags). `GET /health` — состояние шлюза, Ollama, количество моделей.

### Systemd

Создан `llm-gateway.service` — автостарт шлюза после Ollama, restart on failure.

### Исправления stream-протокола

Единый ID для всех чанков одного ответа (был уникальный UUID на каждый чанк). Первый чанк: `delta: {"role": "assistant"}` без content. Финальный чанк: `finish_reason: "stop"` + `usage`. Маркер `data: [DONE]`.

## Актуальный код

Файл: `~/llm-gateway/gateway.py`, версия 0.2.0.

Ключевые характеристики:
- FastAPI + httpx.AsyncClient (singleton, таймаут 600 сек)
- Маршруты: POST /v1/chat/completions, GET /v1/models, GET /health
- Pydantic-модели: ChatMessage, ReasoningConfig, ChatCompletionRequest
- Маппинг параметров: temperature, max_tokens, top_p → options; num_ctx, num_gpu, num_batch → options; reasoning.effort → think
- Reasoning: extract_content_and_reasoning() — разделение content/thinking; estimate_token_split() — приближённое разделение usage
- Stream: stream_generator() с фильтрацией thinking, единым ID, role-only первым чанком, usage в финале
