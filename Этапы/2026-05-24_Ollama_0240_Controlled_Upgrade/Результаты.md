## 3. Метод upgrade

Официальный pipe-installer не использовался как основной путь.

Выбран controlled archive path:

1. Скачать release archive через `aria2c`.
2. Проверить целостность через `zstd -t`.
3. Проверить содержимое через `tar -I zstd -tf`.
4. Остановить `ollama.service`.
5. Создать backup текущего runtime.
6. Заменить `/usr/local/bin/ollama` и `/usr/local/lib/ollama` через extraction в `/usr/local`.
7. Перезапустить `ollama.service`.
8. Проверить runtime, CUDA backend, Ollama API, gateway API.

Первичная попытка скачать `.tgz` вернула `Resource not found`. Это не повлияло на runtime. Правильный asset: `ollama-linux-amd64.tar.zst`.

## 8. Observations

### 8.1. Gateway restart note

After any Ollama runtime replacement, always check and restart `llm-gateway.service` if needed. Gateway validation is mandatory before declaring platform PASS.

### 8.2. Large context VRAM pressure

Gateway smoke with `qwen3.6:27b` under context `131072` showed:

- model size around `30 GB`;
- processor split: `28%/72% CPU/GPU`;
- VRAM used: около `22072 MiB / 24576 MiB`.

Interpretation:

- this is not an upgrade failure;
- it is expected pressure on single RTX 3090 when combining large model + 131K context;
- performance-sensitive lanes should avoid defaulting all models to maximum context.
