## Harness incident

Первоначальный long-run выявил regression harness, а не model-quality failure.

Фактическое состояние нового workspace:

```text
global compaction.reserveTokens = 16384
keepRecentTokens                = 20000
httpIdleTimeoutMs               = 7200000
retry.maxRetries                = 1
project .pi/settings.json       = absent
```

Ранее проверенный `32768/20000` находился только в project-local OpsBoard settings и не был перенесён в новый workspace.

Следствия:

- auto-compaction стартовал примерно на 93.8% вместо 87.5%;
- compaction request упирался в 2h client timeout;
- agent retry автоматически запускал ещё один дорогой long-prefill;
- серверный журнал при этом показывал реальный прогресс, а не зависание.

## Mandatory self-review

После recovery Q6 получила инструкцию не начинать реализацию заново, сохранить first-pass immutable и завершить self-review из текущего workspace.

Self-review включила:

- повторное чтение TASK/spec;
- полный diff;
- все изменённые функции и module interactions;
- regression tests на реальные находки;
- red/green проверку против first-pass snapshot;
- model-differentiated fuzz;
- hostile API sweep;
- повтор полного final gate.

Найдено и исправлено 7 defect classes:

1. explicit null optional keys;
2. concurrent v1->v2 migration race;
3. invalid UTF-8 CLI input;
4. lone surrogate domain validation;
5. legacy `lease_until=NULL`;
6. torn snapshot read;
7. raw SQLite lock errors/read contention path.

Дополнительно пойман и исправлен собственный дефект regression test, не засчитанный как defect production code.

## Methodological result

Главный результат не только в том, что final tests зелёные.

First-pass уже проходил owner evaluator, но обязательная self-review нашла дополнительные реальные дефекты, которые evaluator первой версии не ловил. Поэтому для Q6 закрепляется обязательный pattern:

```text
execution contract
-> implementation
-> first-pass checkpoint
-> full self-review
-> regression tests
-> repair
-> full rerun
-> external review
```
