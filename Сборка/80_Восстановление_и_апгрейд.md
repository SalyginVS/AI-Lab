# Восстановление и обновление

Статус: интеграция RB-11, готов к приёмке фазы A. Назначение: связать процедуры обновления и возврата к принятому состоянию.
Порядок: определить затронутый шаг [00](00_Порядок_сборки.md), сохранить приватные конфиги и данные, выполнить его процедуру, затем [90](90_Acceptance_suite.md).
На действующей лаборатории установка, перезапуск, перезагрузка и перенос ревизий требуют решения владельца. Этот документ сам их не разрешает.

## Обновление и откат

| Компонент | Процедура | Приёмка после операции |
|---|---|---|
| Ollama | Разделы обновления и отката [20](20_Ollama.md); один проверенный архивный способ | Архив заменяет дерево runtime: повторить [40](40_Q6_runtime.md), installed verify, F01–F05 и разрешённый T-MED |
| Модели | Проверка SHA256, импорт и сравнение метаданных по [30](30_Модели.md) | ID Q6 проверить заново; повторить 40 при смене ID; F04, M01–M07; embedding сравнить с принятым эталоном |
| Сервисы | Версионные каталоги, lock, digest, данные и откат по разделу 8 [50](50_Сервисы_Gateway_MCP.md) | Проверки 50, F06, M08, M10–M12 и затронутые сквозные вызовы |
| Клиент | Обновление и откат по [60](60_Клиент_Dell.md), временный HOME | C01–C04, M09; H-1 и границы ADR-031 сохранить |
| Секреты и защита | Ротация по [70](70_Безопасность_и_секреты.md), точные действия по приватному пакету | Приватные F08, C05, внешние сетевые проверки и затронутые сервисы |

Перед обновлением сохранить прежнюю поставку с хешами, конфигурацию и необходимые данные. Откат кода не доказывает обратимость изменения формата данных.
Не выполнять произвольное pip upgrade, замену изменяемого Docker tag или новое получение модели без сверки источника.

## Дрейф по D-9

Выбран вариант автоматических обновлений без hold. Ежедневно выполнять F07 по [90](90_Acceptance_suite.md) и сохранять полный список отличий.
При DRIFT записать пакет, прежнюю и новую версии, дату и источник. Обновлять документы после разбора, ожидания baseline автоматически не менять.
При REVALIDATE сохранить протокол и изменение условий Q6. Согласовать ревалидацию принятой роли по ADR-031. Один короткий ответ не закрывает это требование.

OBS-10-02: установлены ядро 6.8.0-147 и соответствующие модули NVIDIA, работает 6.8.0-146. До перезагрузки владелец выбирает окно и проверяет путь возврата к прежнему ядру.
После перезагрузки проверить работающее ядро и драйвер, выполнить T-FAST и разрешённый T-MED. При расхождении остановиться и действовать по ADR-031.
Даже при успехе коротких проб объём ревалидации принятой роли должен быть согласован. После решения обновить манифест, затронутый runbook и выпустить новую версию паспорта.

## Частичная установка

| Где прервалось | Порядок восстановления и точка решения |
|---|---|
| 10, ОС и диски | Сверить mount и разметку по [10](10_Сервер_ОС_и_драйвер.md); не повторять форматирование существующих данных. Установить состояние пакетов и загрузчика; продолжать после проверок 10 |
| 20, Ollama | Выполнить preflight и проверку файлов по [20](20_Ollama.md). При смешанном дереве вернуть сохранённый архивный backup, затем установить целиком проверенную поставку и повторить 40 |
| 30, модель | Проверить каждый файл SHA256 и метаданные по [30](30_Модели.md). Неполный источник не импортировать. Продолжить с проверенных файлов; не удалять прежнюю модель до принятия новой |
| 40, wrapper | Сначала проверить wrapper, сохранённый ELF и metadata по [40](40_Q6_runtime.md). При обычной ошибке использовать описанный откат; после потери питания сверить backups до повтора. Групповая транзакция не доказана |
| 50, сервисы | Определить, какие каталоги и unit уже переключены. Вернуть прежние согласованные каталоги и приватные конфиги по [50](50_Сервисы_Gateway_MCP.md); не удалять Chroma и volumes. Повторить проверки 4–7 |
| 60, клиент | Вернуть сохранённую конфигурацию и прежнюю поставку по [60](60_Клиент_Dell.md). Проверять в отдельном HOME; к живому профилю переходить после принятия |
| 70, доступ или секреты | Использовать локальную консоль и приватную процедуру восстановления по [70](70_Безопасность_и_секреты.md). Сначала восстановить управляемый доступ, затем проверить потребителей секретов |
| 90, приёмка | Сохранить сырой и оценённый протоколы. Разделить FAIL, DRIFT, REVALIDATE и TEST_DEFECT; повторить только затронутый набор после принятого исправления |

## Перенос RB-07.1 на действующий сервер

Перенос возможен только по отдельному решению владельца. Принимается согласованная пара `health-check.sh` и `pipelines.yaml` из [ревизии](artifacts/services/gateway/revisions/rb07.1/CHANGES.md).
До окна проверить её SHA256SUMS и пройти [офлайн-тест](tests/services/test_healthcheck_revision.py). Приватно сохранить оба живых файла и их хеши.
В окне подготовить оба файла, сверить хеши и права, заменить согласованную пару до возобновления ночного задания. Применить порядок активации gateway из 50.
Проверить загрузку pipeline, выполнить M10 и M11 по 90, затем контролировать следующий cron. Ожидаются 20/20 при выполнении предварительных условий 50.
При неуспехе вернуть оба сохранённых файла и повторить затронутые проверки. Не исправлять принятые исходники на месте ради прохождения теста.
OBS-10-05 о searxng-mcp остаётся отдельным вопросом владельцу: принятая ревизия этой проверки не добавляет.
