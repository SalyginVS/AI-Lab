## Что сделано

### Валидация диапазонов

Все параметры генерации обёрнуты в Pydantic `Field()` с ограничениями. При нарушении диапазона — HTTP 422 с указанием невалидного параметра и допустимого диапазона. Валидация срабатывает до отправки запроса в Ollama.

| Параметр | Диапазон | Обоснование |
|---|---|---|
| `temperature` | 0.0–2.0 | Стандарт OpenAI |
| `top_p` | 0.0–1.0 | Стандарт OpenAI (nucleus sampling) |
| `max_tokens` | ≥ 1 | Положительное целое |
| `frequency_penalty` | -2.0…2.0 | Стандарт OpenAI |
| `presence_penalty` | -2.0…2.0 | Стандарт OpenAI |
| `seed` | ≥ 0 | Целое неотрицательное |
| `num_ctx` | 1–32768 | Защита от OOM (MAX_NUM_CTX) |
| `num_gpu` | ≥ 0 | Количество слоёв GPU |
| `num_batch` | ≥ 1 | Размер батча |
| `repeat_penalty` | 0.0–2.0 | Ollama native |
| `repeat_last_n` | ≥ -1 | -1 = весь контекст, 0 = отключено |

### Проброс penalties — прямой, без аппроксимации

Ключевое открытие Этапа 3: **Ollama нативно поддерживает `frequency_penalty` и `presence_penalty`** через `options`. Это было неверно задокументировано на Этапе 1 как «Ollama не поддерживает». Проверено по актуальной документации Ollama API — оба параметра пробрасываются в llama.cpp, который реализует те же аддитивные штрафы, что и OpenAI.

Результат: никакой аппроксимации через `repeat_penalty` не нужно. Прямой маппинг 1:1.

### Новые параметры

`seed` — для воспроизводимости генерации. Пробрасывается в `options.seed`. Подтверждено тестом: два запроса с одинаковым seed и temperature=0.0 дали идентичные ответы.

`repeat_penalty` — Ollama-native мультипликативный штраф за повторения (отличается от аддитивных OpenAI penalties). Пробрасывается в `options.repeat_penalty`.

`repeat_last_n` — окно контекста для repeat_penalty. Пробрасывается в `options.repeat_last_n`.

### Логирование

Добавлено структурированное логирование через Python `logging` (логгер `uvicorn.error` → systemd journal):

| Уровень | Содержание |
|---|---|
| INFO | Каждый запрос: request_id, model, stream, effort |
| DEBUG | Полный dict options, отправленный в Ollama |
| WARNING | Двойной штраф: repeat_penalty + frequency/presence_penalty одновременно |

Просмотр логов: `sudo journalctl -u llm-gateway | grep REQ`. Включение DEBUG: `uvicorn gateway:app --log-level debug`.

Примечание: изначально логгер был создан как `logging.getLogger("llm-gateway")` — не работал, потому что у него не было handler (обработчика). Исправлено на `logging.getLogger("uvicorn.error")` — используется handler, уже настроенный uvicorn.

## Исправленная ошибка в документации

На Этапе 1 было записано: «frequency_penalty и presence_penalty — терминология OpenAI. Ollama нативный API их НЕ поддерживает (у Ollama есть repeat_penalty, но это другой параметр с другой семантикой)».

Это неверно. Ollama нативно поддерживает оба параметра в `options` — подтверждено документацией Ollama API (https://github.com/ollama/ollama/blob/main/docs/api.md) и OpenAI-совместимым эндпоинтом Ollama (https://docs.ollama.com/api/openai-compatibility). Параметры пробрасываются в llama.cpp.
