# Этап — OpenCode controlled terminal-agent lane

## Задача

Проверить OpenCode как controlled terminal-agent контур для AI Lab RTX 3090:

```text
Ubuntu laptop `vladimir-Precision-5560`
  -> OpenCode v1.15.0 user-local baseline
  -> provider `ailab`
  -> llm-gateway `http://192.168.0.128:8000/v1`
  -> model `qwen3.6:27b`
```

Цель этапа — не сразу пустить OpenCode в AI-Lab repo, а сначала подтвердить:

- provider/model visibility;
- gateway completion path;
- server-side gateway evidence;
- permission boundary;
- read-only and bounded-edit wrapper behavior;
- absence of lingering `opencode` processes after runs;
- пригодность профилей для дальнейших sandbox/repo tests.

## Source-of-truth boundary

Канонический контур документации:

```text
/home/vladimir/llm/AI-Lab
git@github.com:SalyginVS/AI-Lab.git
```

Сервер `192.168.0.128` является runtime filesystem, не documentation/source-of-truth контуром.

## Current operational decision

### Approved for now

```text
oc-ailab-readonly
```

Use for:

- sandbox/repo analysis;
- read-only code inspection;
- documentation review;
- no modifications.

```text
oc-ailab-edit
```

Use for:

- sandbox bounded edits;
- later controlled repo tests only after explicit approval;
- small scoped file changes;
- mandatory post-check with `git diff` / file content / tests.

### Not approved yet

```text
OpenCode as autonomous agent in AI-Lab repo
OpenCode with bash enabled
OpenCode with task/subagent enabled
OpenCode with webfetch/websearch enabled
OpenCode with external_directory access
OpenCode with edit=ask in non-interactive `opencode run`
```

## Operational rules learned

1. Before switching OpenCode profile/scenario, stop current run and verify no lingering `opencode` process.
2. Do not give contradictory tasks like “modify file” under `edit=deny`.
3. For `opencode run`, `edit=ask` auto-rejects in current scripted behavior and can still exit `0`.
4. Treat model self-report about available tools as unreliable.
5. Source of truth is observed tool behavior: `Invalid Tool`, filesystem state, diff, logs, metrics.
6. For bounded edit, `edit=allow` + `bash/task/web/external_directory=deny` is currently the working scripted profile.
7. Always verify post-state; do not trust exit code alone.

## Step RW — repo-write validation against AI-Lab repo

### Цель

Проверить, можно ли использовать `oc-ailab-edit` для строго ограниченной правки внутри AI-Lab documentation repo без повышения OpenCode до autonomous repo agent.

### Scope

Разрешённая директория:

```text
Этапы/2026-05-15_OpenCode_Controlled_Terminal_Agent/repo_write_probe/
```

Разрешённый файл:

```text
Этапы/2026-05-15_OpenCode_Controlled_Terminal_Agent/repo_write_probe/README.md
```

### Выполненный сценарий

1. Перед запуском проверено отсутствие `opencode` процессов.
2. Repo baseline был чистым: `## main...origin/main`.
3. Disposable probe-файл создан вручную.
4. `oc-ailab-edit` запущен только на директорию `repo_write_probe`.
5. OpenCode выполнил видимые операции:
   - `Read README.md`
   - `Edit README.md`
6. Файл получил ожидаемое содержимое:

```text
Repo-write validation content written by OpenCode bounded edit.
```

7. После запуска не осталось `opencode` процессов.
8. Token/secrets grep по probe-директории прошёл:

```text
TOKEN_SECRET_GREP=PASS_NO_MATCH
```

9. Evidence commit создан и запушен:

```text
adee92f test: validate OpenCode bounded repo write
```

Remote alignment после push:

```text
HEAD=adee92f
ORIGIN_MAIN=adee92f
git status: ## main...origin/main
```

### Уточнение по tool boundary

Корректная формулировка:

```text
bash/task/web/external_directory: no successful use observed;
denied by wrapper policy;
visible OpenCode trace showed only read/edit operations inside scoped directory;
filesystem/git post-state showed no boundary breach.
```

Это не является raw internal tool-call audit log. Для smoke-test уровень доказательства достаточен, но утверждение не следует формулировать как абсолютное “tools were never attempted”.

### Итоговое решение

```text
REPO_WRITE_SMOKE=PASS
OPEN_CODE_REPO_WRITE_MODE=allowed_only_for_small_scoped_docs_edits_with_manual_review
AUTONOMOUS_AGENT_READY=no
```

### Разрешённый режим

`oc-ailab-edit` разрешён только для:

- малых scoped documentation edits;
- заранее указанной директории через `--dir`;
- ручного review результата;
- обязательных post-checks: `git status`, `git diff`, secrets grep, проверка отсутствия `opencode` процессов;
- commit/push только после review.

### Запрещено

- autonomous repo agent;
- bash-enabled profile;
- task/subagent-enabled profile;
- webfetch/websearch-enabled profile;
- external_directory access;
- `--dangerously-skip-permissions`;
- repo-wide write без явного scope.
