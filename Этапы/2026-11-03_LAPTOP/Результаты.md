# LAPTOP-01 и LAPTOP-02: обследование и восстановление клиента Lenovo

## Решения владельца

Lenovo выбран основным ноутбуком AI-Lab с 2026-11-03, Dell переведён в резерв в условиях дефицита электроэнергии и питания от резерва; сравнительных замеров энергопотребления нет (решение владельца LAPTOP-01). Владелец выбрал свежую среду: пользовательский Node.js 26.13.0 вместо принятого на Dell 22.22.1 и VS Code 1.144.1 вместо 1.142.0 комплекта (LAPTOP-02:A3.0,A5.1, вердикт приёмщика).

## LAPTOP-01: обследование и первая документация

2026-11-03 проведено только read-only обследование оборудования, ОС, инструментов, окружения Pi, Obsidian, SSH и рабочих копий (LAPTOP-01:L01-L10). DMI `product_version` = `IdeaPad Slim 3 16IAH8`, `product_name` = `83ES`. ОС Ubuntu 26.04.1, ядро `7.0.0-42-generic`, i5-12450H, 14 GiB RAM по `free`, Intel UHD без NVIDIA (LAPTOP-01:L01-L04). Ветка `docs/laptop-01-lenovo-primary-20261103` с коммитом `cecc031` содержала первую документационную версию, где Lenovo стал основным ноутбуком, но Pi-клиент ещё не был восстановлен. История коммита сохранена; его устаревшие утверждения исправляются следующим коммитом LAPTOP-03.

## LAPTOP-02: восстановление Pi и три остановки

1. **Ранее существующий `~/.pi`.** Найден неизвестный профиль со следами Pi 1.0.4 и Q5/KAT/RVN. Изменения приостановлены до полного приватного резерва; затем установлен эталон, а `auth.json` только дополнен `ailab-ollama` (delta-1 A1.5; LAPTOP-02:A4).
2. **npm и lock.** npm 12.2.1 отказал с `EUSAGE` на отсутствующих `@esbuild/*@0.28.2`; приёмщик воспроизвёл проблему. Установка возобновлена с npm 9.2.0 через `npx` после проверки integrity без изменения lock (LAPTOP-02:A3,A3.1-A3.4; [Грабли 094](../../Грабли/094_npm_ci_lock_requires_npm9.md)).
3. **Первоначальная недоступность сервера.** HTTP-доступ отсутствовал из-за выключенного коммутатора. После включения коммутатора HTTP и короткие живые пробы завершились успешно без изменения серверной конфигурации (LAPTOP-02:B1-B4).

Итоговая установка: Pi 1.0.3 в `~/.local/opt/pi/1.0.3`, генератор конфигурации с `ailab-ollama` и Q6 по умолчанию, Q27 дополнительной моделью, `pi-q27` совпал с артефактом; fd 10.5.0 и rg 15.2.0 (LAPTOP-02:A3-A4). Obsidian 1.15.0, `wl-clipboard` 2.2.1-2build1, ранее установленный `python3-pexpect` 4.9-4; основная рабочая папка на Lenovo `~/llm/AI-Lab` (LAPTOP-02:A6-A7). SSH-алиас `llm` создан, вход по паролю, без проверки SSH-соединения (LAPTOP-02:A8).

## Вердикт приёмщика и границы допуска

**Claude, 2026-11-03: `ACCEPTED_WITH_LIMITATIONS`.** Принятая поверхность ADR-031/ADR-032 (Pi 1.0.3, принятая конфигурация, прямой Ollama) воспроизведена на Lenovo; отличается среда исполнения Pi (Node). Запуски Q6 и Q27 с Lenovo допускаются в границах ADR-031 и ADR-032 с ограничением 1. По ADR-030 поверхность та же, ADR не изменяются (вердикт приёмщика LAPTOP-02).

Пять ограничений (не недостатки):

1. Pi на Lenovo работает на Node.js 26.13.0 против 22.22.1 Dell, решение владельца. Эквивалентность проверена по Pi, конфигурации, полям запросов и коротким живым ответам; полный Q6 61/61 и испытания Q27 на Lenovo не повторены (LAPTOP-02:A3-A5,B1-B4).
2. VS Code 1.144.1 вместо 1.142.0, C03 DRIFT, решение владельца (LAPTOP-02:A5.1).
3. Регистрация Obsidian-папки выполнена исполнителем через файл реестра приложения, а не через окно; состояние `.obsidian/` после первого открытия не зафиксировано (LAPTOP-02:A7).
4. npm 9.2.0 взят из npm registry через `npx`, а не пакетом Ubuntu; результат побайтно совпал с эталоном C01 (LAPTOP-02:A3.1-A3.4).
5. Приёмка по сырым выводам исполнителя, без независимого воспроизведения на Lenovo (вердикт приёмщика LAPTOP-02).
